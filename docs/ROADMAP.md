# XProbe 改进路线图

> 基于 2026-09-03 第二轮代码审查(修复记录见 git log)与 Nezha / Komari / NodeGet 功能对标。
> 安全红线(S1-S9)不因对标而放松:涉及"控制通道""命令执行""多租户"的对标项一律列入**明确不采纳**。

## 一、近期工程改进(现状债,按优先级)

| 优先级 | 项 | 说明 |
|--------|-----|------|
| P1 | 详情页延迟格子 60 点历史 API | 当前详情页格子只显示最新一轮;Hub 已有 `PingRows`,补 `GET /servers/:id/ping-history` 即可 |
| P1 | Limiter 定时 GC | 限速器仅在拒绝时回收,大量唯一 IP 低频扫描下慢泄漏;改为后台定时回收 |
| P1 | 前端 WS 401 重连循环 | 会话过期后 /ws/dashboard 无限重连;收到策略拒绝时引导回登录页 |
| P2 | ChartCard 生命周期 | 双 useEffect 重复 init/每次数据 dispose 重建;合并为单 effect + resize 监听,响应主题切换 |
| P2 | repo_record 命名 | `net_rx_avg` 实际存窗口峰值,改名或改语义对齐设计文档 5.3(取均值) |
| P2 | Linux 实机验证 | systemd 单元(含 AmbientCapabilities)、sysctl、setcap、一键安装全链路需在真实 VPS 验证(开发环境为 Windows) |
| P3 | Makefile release 目标 | `make release` 本地出全矩阵产物 + SHA256,与 CI 保持同一实现 |

## 二、三个对标探针的可借鉴功能

### Nezha(哪吒监控)——功能最全,按红线筛选

| 功能 | 采纳建议 | 说明 |
|------|---------|------|
| **服务监控(HTTP/TCP/ICMP 拨测 + 在线率状态页)** | **P1 采纳** | 与"服务器探针"最互补的能力:Server 侧对服务端点做可用性拨测,产出"在线率百分比 + 故障时间线",复用现有告警引擎与分享页。Server 发起探测**不违反 S1**(S1 限制的是 Server→Agent 控制通道) |
| 通知渠道数量(20+:Discord/Slack/飞书/钉钉/Bark/群晖…) | **P2 采纳部分** | 通道抽象已就绪,每加一个就是一个小 sender;优先 Discord/Slack/飞书 |
| 多主题系统(用户可选面板主题) | P2 | 当前外观配置(背景/卡片风格/强调色)已是雏形;主题包机制 v2 评估 |
| 报表/流量图表增强(月/年度汇总页) | P2 | 数据已有(metric_records_daily),补一个汇总视图 |
| 2FA/OAuth2 登录 | P2 | TOTP 已在 v2 路线图;OAuth2 依赖外部 IdP,谨慎评估 |
| API Token(供第三方读取只读数据) | P2 | 与分享页白名单同思路,签发只读 Token |
| 计划任务 / WebSSH 终端 / 文件管理器 | **不采纳** | 违反 S1/S4(控制通道与远程执行),XProbe 的核心差异化恰恰是砍掉这些 |
| Agent 自动更新 | 不采纳 | 同上;保持手动升级 + 面板版本提示 |
| DDNS / NAT 穿透 | 不采纳(v2 再议) | 与探针主线无关,显著扩大攻击面 |

### Komari(轻量平替)——对标"极简部署体验"

| 功能 | 采纳建议 | 说明 |
|------|---------|------|
| 多种部署方式一键化(脚本/Docker/二进制) | **已对齐** | install-server.sh / Docker / compose 已覆盖 |
| 多用户 Token 隔离访问 | 观察 | 违反 S5 单管理员;若做"只读观察者账号"可评估,不引入写权限分离 |
| Agent 占用极低的宣传口径 | **P1 借鉴做法** | 补 Agent 内存/CPU 占用基准测试进文档(采集器全 /proc 读取,理论占用极低,需数据支撑) |
| Web 面板实时图表自定义布局 | P3 | bento 化仪表盘,体验层增强 |

### NodeGet(VPS 圈审美标杆)——视觉与 VPS 玩家功能

| 功能 | 采纳建议 | 说明 |
|------|---------|------|
| 三视图(卡片/表格/地图) | **P2 补地图** | 卡片/表格已交付;地图+GeoIP 按设计文档随 v2 落地(依赖 MaxMind 注册) |
| 到期/成本管理增强(合计/币种换算/续费提醒) | **P2 增强** | 已有字段与告警;补"成本汇总页"(按币种分组合计 + 手动汇率折算) |
| 标签分组 + 筛选 | **已对齐** | v1 已交付 |
| IPv4/IPv6 双栈延迟分列 | **已对齐** | v1 已交付 |
| 公开状态页多模板(StatusShow 类) | P2 | 分享页已交付;模板/自定义程度 v2 增强 |
| Js Worker 插件系统 | **不采纳** | 服务端执行任意 JS,违反 S4 |
| 社区主题生态 | 观察 | 需先有主题系统 |

### 同类项目补充观察(搜索中发现)

- **Beszel**:极简部署 + 低占用方向,印证 Agent 资源基准测试值得做
- **ServerStatus(xOS)**:DDNS/NAT/API Token 管理的取舍可参考

## 三、建议的实施顺序

1. **P1(短期)**:延迟历史 API + Limiter GC + WS 401 处理 + Agent 占用基准文档 + Linux 实机验证
2. **P2(中期)**:服务监控拨测 + 在线率状态页(最大差异化补强)→ Discord/Slack/飞书通知 → 地图+GeoIP → 成本汇总页 → TOTP
3. **P3(远期)**:主题系统 / 报表汇总 / API Token / bento 布局

每项实施仍受 S1-S9 约束:凡需 Server 向 Agent 下发指令、执行命令、引入多租户写权限的功能,一律不做。
