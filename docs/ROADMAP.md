## 二、三个对标探针的可借鉴功能

### Nezha(哪吒监控)——功能最全,按红线筛选

> 2026-09-03 更新:服务监控 ✅(HTTP/TCP/ICMP 拨测 + 45 天在线率格 + 状态转移通知 + 分享页集成);报表/汇总页 ✅(月度流量堆叠图 + 成本合计/币种换算 + 续费提醒)。

| 功能 | 状态 | 说明 |
|------|------|------|
| **服务监控(HTTP/TCP/ICMP 拨测 + 在线率状态页)** | ✅ 已实现 | `services`/`service_daily` 表 + 拨测引擎(独立 goroutine, 状态转移通知) + 服务页(45 天日格/最近 64 次条) + 分享页服务区。Server 发起探测不违反 S1 |
| 报表/流量图表增强(月/年度汇总页) | ✅ 已实现 | `GET /report/traffic` + 报表页:近 12 月流量堆叠图、成本按币种合计与手动汇率折算 CNY、30 天续费提醒列表 |
| 通知渠道数量(20+:Discord/Slack/飞书/钉钉/Bark/群晖…) | ⏳ P2 未做 | 通道抽象已就绪,每加一个就是一个小 sender;优先 Discord/Slack/飞书 |
| 多主题系统(用户可选面板主题) | ⏳ P2 未做 | 当前外观配置(背景/卡片风格/强调色)已是雏形;主题包机制 v2 评估 |
| 2FA/OAuth2 登录 | ⏳ P2 未做(TOTP 按早期决策移 v2) | OAuth2 依赖外部 IdP,谨慎评估 |
| API Token(供第三方读取只读数据) | ⏳ P2 未做 | 与分享页白名单同思路,签发只读 Token |
| 计划任务 / WebSSH 终端 / 文件管理器 | **不采纳** | 违反 S1/S4(控制通道与远程执行),XProbe 的核心差异化恰恰是砍掉这些 |
| Agent 自动更新 | 不采纳 | 同上;保持手动升级 + 面板版本提示 |
| DDNS / NAT 穿透 | 不采纳(v2 再议) | 与探针主线无关,显著扩大攻击面 |

## 三、建议的实施顺序(2026-09-03 清点)

1. **P1(短期)**:✅ 全部完成(延迟历史 API / Limiter GC / WS 401 / 基准文档 / make release);仅 Linux 实机验证待真实 VPS
2. **P2(中期)**:✅ 服务监控拨测+在线率状态页 / 报表汇总页 / 地图视图(轻量) / 成本汇总+续费提醒 / 仪表盘布局;⏳ **未做**:Discord/Slack/飞书通知、多主题系统、TOTP(按早期决策移 v2)、API Token、MaxMind 城市级 GeoIP
3. **P3(远期)**:⏳ 完整 bento 拖拽布局 / 主题包生态

每项实施仍受 S1-S9 约束:凡需 Server 向 Agent 下发指令、执行命令、引入多租户写权限的功能,一律不做。
